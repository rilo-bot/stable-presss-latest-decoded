## 3. What is genuinely strong

Worth recording, because it is most of the code and it should not be re-litigated.

**Soft delete lives in one place.** `lib/db.ts` folds `deletedAt: null` into
`find`, `count`, `findById`, `updateOne`, `updateOneIf`, `claimOne`, `addToSet`,
`pullFrom` and `deleteOne`. No route re-implements it, so no route can forget it.
The one documented escape hatch (`rawCollection`, for reactions' hard delete)
explains exactly why it exists and why nothing else may use it.

**The concurrency primitives are real, not decorative.** `updateOneIf` folds the
condition into the query filter so match-and-update is one atomic server operation;
`claimOne` uses `findOneAndUpdate` so two worker replicas cannot take the same job;
`addToSet`/`pullFrom`/`pullFromAll` mean array writes no longer lose a concurrent
update. These are the fixes for a class of bug that read-modify-write would
reintroduce silently.

**No role slug appears in `lib/rbac.ts`.** Every gate asks what the account may
*do*. The two role-family tests were deleted rather than deprecated so the compiler
enumerated every call site. `canAccessNewsroom` is "holds a staff role" and the
reasoning for removing `newsroom.access` from the catalogue is recorded in the file
itself.

**Auth fails closed.** Missing `JWT_SECRET` under `PROD=true` calls
`process.exit(1)` — deliberately not `throw`, so the `uncaughtException` guard in
`index.ts` cannot keep an insecure process alive. Session revocation
(`tokenVersion`) and suspension are read from the live user document on every
request, so the JWT carries no authorization data at all.

**`POST /api/admin/seed` self-disables.** It refuses once `superadminHolderCount()`
is non-zero, so the bootstrap path closes itself rather than depending on someone
remembering to unset `SETUP_SECRET`. Recovery is a script requiring `MONGODB_URI`
(infrastructure access), not an HTTP route.

**44 indexes, each with a documented reason** (`lib/ensureIndexes.ts`), including
the two uniques that *are* business rules rather than optimisations:
`reactions (targetType, targetId, userId)` is the one-reaction-per-reader rule, and
`commentReports (commentId, userId)` is what makes `reportCount` a count of people.
The file also explains where it deliberately adds *no* index (unfiltered register
reads) rather than adding decoration that costs write throughput.

**Private upload kinds 404 rather than 403** — a 403 would confirm an evidence file
exists at that key.

**Error handling is honest at the edges.** The 413 branch in the error handler
surfaces `PayloadTooLargeError` as a real limit message instead of a generic 500,
and `agentEditor`'s ingest distinguishes timeout / retryable-upstream / bad-file so
a provider blip does not get blamed on the user's document.

## 4. Findings

### F1 — Critical: `POST /api/auth/request-otp` has no rate limit

`routes/auth.ts:51`. Unauthenticated. Every call writes an `otps` row and sends an
email through Resend. There is no throttle of any kind — not per IP, not per
address.

Two costs: an attacker can bill the Resend account and mailbomb any known address,
and the `otps` collection grows on demand (deletes there are soft, so the rows
stay). `routes/admin.ts:26` carries a comment calling `/seed` "the ONLY unthrottled
write in the product" — that is no longer true, and this one is reachable without a
secret.

**Fix:** `rateLimit('otp-request', 5, 15 * 60_000)` keyed by IP, plus a second
per-address bucket so rotating IPs cannot target one mailbox.

**Also note (not a bug):** the endpoint answers 404 "No account found" for login and
409 "An account with this email already exists" for signup, which is account
enumeration. That is a deliberate UX trade — recorded here so it is a decision, not
an oversight.

### F2 — Critical: six model endpoints are anonymous *and* unmetered

| Endpoint | Body cap | Upstream cost |
| --- | --- | --- |
| `POST /api/agent/story/chat` | 30 MB | OpenRouter |
| `POST /api/agent/blog/chat` | 30 MB | OpenRouter |
| `POST /api/agent/profile/chat` | 30 MB | OpenRouter |
| `POST /api/agent/article/chat` | 30 MB | OpenRouter |
| `POST /api/agent/voice/transcribe` | 25 MB raw audio | OpenAI STT |
| `POST /api/agent/voice/speak` | — | OpenAI TTS |

All six use `attachAccountOptional` — which never rejects — and none carry
`rateLimit`. The four chat routes sit behind the 30 MB `jsonAgent` parser
(`index.ts:59`), so an anonymous caller can post 30 MB of PDFs and images straight
at the model, repeatedly.

The pattern is already established elsewhere: `/api/agent/chat` is 20/min,
`/api/agent/compose` is signed-in + 60/5min, `/api/agent/instant` is staff-only +
40/5min with a comment explaining exactly this risk. These six were simply missed.

**Fix:** the four studio routes back staff-only screens — swap
`attachAccountOptional` → `attachAccount` + `canAccessNewsroom`, and add
`rateLimit`. Voice is used by the reader-facing concierge, so it needs at minimum a
rate limit; prefer signed-in.

This is the "guest-reachable unmetered endpoints" item from
[AI-AGENTS-AUDIT.md](AI-AGENTS-AUDIT.md), still open, now enumerated exactly.

### F3 — High: the authorization gate loads two entire collections

`lib/rbac.ts:152-153`, inside `accountCanManageHorse`:

```ts
const horses = await db.collection('horses').find()
const links  = await db.collection('horsePartyLinks').find()
```

Every horse and every horse↔party link is pulled into the API process, then
`writableHorseIds` filters in Node. Because this is *middleware*, it runs before the
handler on **every non-staff write** to six mounts — `horses`, `horsePartyLinks`,
`sales`, `reports`, `mediaItems`, `racingEntries` (27 endpoints). On PUT it can run
twice (pre-image plus the re-point check at `rbac.ts:219`).

The cost scales with the size of the register, not with the request. Two indexes
already exist that would serve a scoped query
(`partyMemberships (userId, status, deletedAt)` and
`partyMemberships (partyId, status, deletedAt)`).

**Fix:** resolve the account's party/org ids first, then
`db.collection('horsePartyLinks').find({ party_id: { $in: partyIds } })` and check
membership of the target id — never the whole register.

### F4 — High: `ownedRecordRouter` list route loads the whole collection

`lib/ownedRecordRoutes.ts:60`. `GET /` does a bare `find()` and filters visibility
in Node via `visibleRecords`. Affects `/api/mediaItems` and `/api/racingEntries`.
Same shape as F3, and there is no pagination either, so the response grows without
bound as well.

**Fix:** push the visibility predicate into the query —
`{ $or: [{ createdByUserId: id }, { 'sharedWith.userId': id }] }` for non-staff —
and add `limit`/`skip`.

### F5 — Medium: 20 unpaginated full-collection reads

Bare `.find()` with no filter and no `limit`:

`routes/horses.ts:28,39` · `routes/parties.ts:15` · `routes/races.ts:13` ·
`routes/horsePartyLinks.ts:14` · `routes/sponsors.ts:29` ·
`routes/breakingNews.ts:30` · `routes/podcastEpisodes.ts:65` ·
`routes/reports.ts:17` · `routes/sales.ts:14` · `routes/tipperProfiles.ts:44` ·
`routes/tips.ts:54` · `routes/staff.ts:113` · `routes/organisations.ts:96,100` ·
`routes/magazinesV2.ts:226` · `lib/roleRegistry.ts:189` · `lib/seedRoles.ts:113` ·
`lib/agent/tools.ts` (9 sites) · `lib/agent/capabilities.ts:240-241`

`lib/ensureIndexes.ts` names this explicitly and declines to add indexes for it:
*"an index cannot make an unfiltered scan cheaper… what those routes actually need
is pagination; until they have it, the scan is the honest cost."* So it is tracked,
not hidden — but it is the top scalability item and it is now spread across the
public register endpoints, the AI tool layer and the role registry.

**Fix:** cursor pagination on the register list routes, starting with the ones the
public site hits (`horses`, `parties`, `races`, `podcastEpisodes`).

### F6 — Medium: `GET /api/newsroom/summary` loads five collections per request

`routes/newsroom.ts:60-64` reads all of `articles`, `horses`, `parties`, `races` and
`issues` on every call. Staff-only, but this is the first screen every staff member
opens, so it is the most frequently paid instance of F5.

**Fix:** replace with `count()` + small `aggregate()` rollups — the same change
already made to `routes/metrics.ts`, which now uses four `count()` calls where it
used to fetch four collections.

### F7 — Medium: `POST /api/agent/editor/ingest` is unmetered

`routes/agentEditor.ts:42`. Staff-gated (so not F2), but a 50 MB PDF/image OCR + LLM
pass with **no** rate limit. One staff account in a retry loop can spend
significantly. Every other model endpoint that got a limit got one for this reason.

**Fix:** `rateLimit('agent-ingest', 20, 5 * 60_000)`.

### F8 — Medium: rate limiter and role registry are per-process

`lib/rateLimit.ts` is an in-memory `Map`; `lib/roleRegistry.ts` caches roles in
process. Both files say so. The moment the API runs more than one replica, every
limit in §2 silently multiplies by the replica count, and a role edit takes effect
on one replica at a time.

**Fix:** not urgent while the API is single-instance, but it must be resolved before
scaling out. Record it as a scale-out precondition, not a bug.

### F9 — Low: `findById` masks driver errors as "not an ObjectId"

`lib/db.ts:112-116` (and the same shape in `updateOne`, `updateOneIf`, `addToSet`,
`pullFrom`, `deleteOne`):

```ts
try   { doc = await db.collection(name).findOne({ _id: new ObjectId(id) }) }
catch { doc = await db.collection(name).findOne({ _id: id as any }) }
```

The `catch` is meant for the `ObjectId` constructor throwing on a non-hex id, but it
also swallows any error from the `findOne` inside it — a transient driver failure is
misread as "must be a string key" and retried as a second query.

**Fix:** validate with `ObjectId.isValid(id)` and branch, rather than using `catch`
as control flow.

### F10 — Low: `cors({ origin: '*' })`

`index.ts:41`. Safe as written, because auth is Bearer-only with no cookies — there
is nothing for a hostile origin to ride on. Recorded so that whoever later adds a
cookie knows this line has to change in the same commit.

### F11 — Housekeeping: `repro.tmp.ts` in the repo root

Untracked scratch file probing `fitFontSize`/`refitText`. Delete it.
